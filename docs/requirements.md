# Tutorial Dock 要件定義（MVP）

状態：仕様策定版（2026-10-12）。本書の「確定要件」は会話上の合意内容を記録したものであり、実装・検証済みを意味しません。

## 1. 目的と対象

講師がTableau等の操作画面を維持しながら、短い手順説明と必要時の画像資料を参加者に提示し、Canva等の説明資料への頻繁な画面切り替えを減らす。

- 対象：Windowsでオンライン画面共有する講師。参加者側へのインストールは不要。
- 初期ユースケース：Tableau Desktopのハンズオン。他アプリでも同じ仕組みを利用可能にする。
- 共有前提：対象ディスプレイの画面全体を共有する。個々のアプリウィンドウ共有で別ウィンドウが映ることは保証しない。

## 2. 確定した機能要件

### R-01 ガイドバー

- 選択ディスプレイの画面上端に、タイトルバー・OS標準枠のないガイドバーを置く。
- 通常表示時は高さ固定。暫定目標は約90px。ステップ切り替えによって高さを変えない。
- 左側：ステップ番号／総数、タイトル、短い説明。右側：ステップで定義したボタン、前／次、進捗、設定操作。
- 教材のボタンは0個以上。右側に収まらない場合は「その他」にまとめ、ガイドバーを高くしない。
- 明示的な操作により薄い帯へ折りたためる。暫定目標は約30–36px。展開・折りたたみで予約作業領域の高さも更新し、ステップ位置は保持する。完全非表示はMVP対象外。

### R-02 Windows作業領域

- Windows AppBar API等による画面上端の領域予約を実現し、通常の最大化アプリがバーを避けることを目指す。
- 予約・サイズ変更・ディスプレイ切り替え・終了時に作業領域を適切に更新／解放する。
- 予約できない場合は通常の最前面ウィンドウへフォールバックし、状態を利用者に示す。ただし、AppBarの正常動作をMVP完成条件から外さない。
- 画面共有アプリや対象アプリのフルスクリーン動作など、OS側の例外は検証して制約を明記する。

### R-03 ディスプレイ

- 初回起動時はWindowsのメインディスプレイに表示する。
- 設定メニューから表示先を選べる。旧ディスプレイの予約を解放し、新しいディスプレイ上端へ移動して予約する。
- 説明スライドは選択ディスプレイの中央に開く。
- ディスプレイ切断時は使用可能なディスプレイへ退避する。
- 選択先の永続記憶、会議アプリの共有画面自動検出はMVP対象外。

### R-04 起動・教材選択

- 起動直後は空のガイドバーを表示し、「教材を開く」操作を提供する。
- 読み込むまではステップ移動や教材ボタンを無効化する。
- 任意のローカル .yaml / .yml をファイルダイアログから選択できる。画像パスはそのYAMLの所在ディレクトリを起点に解決する。
- 正常に読み込めたら第1ステップを表示する。別教材の選択も可能とする。
- 前回の教材の自動読み込みはMVP対象外。通常利用はオフラインで成立する。

### R-05 ステップとアクション

- 教材は順序付きステップを持ち、各ステップは固有ID・タイトル・説明文・0個以上のボタンを持つ。
- ステップはガイドバーの前／次ボタンで切り替える。先頭／末尾では範囲外への移動を防止する。
- ボタンはアクション種別を明示する拡張可能な構造とし、MVPで実行できる種別は `image` のみ。
- `url` や `navigate` 等は将来候補であり、MVPで使えるものとして扱わない。未対応アクションは読み込み時の致命的エラーとする。

### R-06 画像説明ウィンドウ

- 画像ボタンを押すと、選択ディスプレイ中央に大きな枠なしの独立ウィンドウを開く。ディスプレイ全体は覆わず、Tableau等が背景に残る。
- PNG/JPEG/WebPを対象とし、初期表示では縦横比を維持して画像全体を収める。
- マウスホイールとUIの＋／−でズーム、拡大後はドラッグで移動、初期倍率にリセット可能とする。
- 明示的な閉じるボタンで閉じられる。閉じても教材ステップと背後の操作アプリの状態を維持する。
- ズーム状態は画像を開くたびに初期化する（暫定動作）。
- グローバルショートカットは設けない。Escキーによるウィンドウ終了もMVP対象外。

### R-07 管理操作・再読み込み

- ガイドバー右端の設定メニューから「教材を開く」「再読み込み」「表示先ディスプレイ」「終了」を利用できる。
- 再読み込みは明示操作時だけ実行し、ファイル変更を自動反映しない。
- 成功時は現在のステップIDに対応するステップを維持し、IDが消えていれば先頭へ移動する。
- 失敗時は直前の正常な教材を維持する。画像ウィンドウ表示中はその表示を即時差し替えず、閉じて再度開いたときに更新する。

### R-08 エラー対応

- 致命的：YAML構文不正、ステップの必須要素・構造の不正、ステップID重複、未対応アクション。新しい教材への切り替え／再読み込みを中止し、直前の正常な状態を保持する。
- 軽微：参照画像の欠落・読み取り不能。該当ボタンを無効化し、他のステップは利用可能とする。
- エラーや警告には可能な範囲でファイルパスとステップIDを提示する。教材が不正でもアプリ本体や対象アプリを停止させない。

### R-09 配布と操作

- Windows向けインストール不要のポータブルexeとしてGitHub Releasesから配布する。
- Node.jsやElectronの別途導入なしで利用できるよう、必要な依存物を同梱する。
- 講師の主要操作はマウスのみで完結できる。キーボードショートカットへの依存はない。
- 自動更新・署名済み配布はMVP必須ではない。未署名exeへのWindows SmartScreen警告は想定上の制約として案内する。

## 3. 非機能要件

- 継続性：教材の一部不備やAppBar予約失敗が、他アプリの操作を妨げない。
- 画面共有の可読性：1080p等の典型的な共有環境で文字とボタンを視認・操作できることを手動検証する。
- 安全性：画像参照はローカル教材を前提とし、任意のコード実行や教材由来のスクリプト実行を認めない。ファイルパスとUIのセキュリティ境界を設計で明確にする。
- 復旧性：通常終了時に作業領域を解放し、異常終了・ディスプレイ構成変化からの復旧を重点検証する。
- 携帯性：アプリ本体と教材は別管理とし、教材フォルダを移動しても相対参照で利用できる。

## 4. MVP受け入れシナリオ

1. クリーンなWindows環境でポータブルexeを起動し、空の枠なしガイドバーがメインディスプレイ上端に表示される。
2. AppBar領域予約が成立し、Tableau等の通常の最大化ウィンドウがガイドバーを避ける。
3. YAMLを選択すると第1ステップが現れ、前／次ボタンで順番に進行できる。任意ボタンは右側、あふれたボタンは「その他」にある。
4. 画像ボタンから中央の枠なし画像を表示し、ズーム・パン・リセット・閉じるがマウスのみでできる。
5. 折りたたみ／展開時にWindows作業領域が連動し、ステップ位置が維持される。
6. 表示先ディスプレイを変更すると、予約が旧画面から新画面に移り、画像ウィンドウも選択画面中央に表示される。
7. YAMLを修正して手動再読み込みするとステップIDに応じて位置を維持し、読み込み失敗時は直前の教材が残る。画像欠落時は該当ボタンのみ無効化される。
8. ディスプレイ全体をオンライン共有し、Tableau操作とガイド・画像表示を同じ共有映像で確認できる。
9. 終了時にWindowsの予約領域が解放される。AppBar障害時にはフォールバックが動作するが、正常なAppBar動作の実証は必須。

## 5. MVP対象外

教材編集GUI、Canva API連携、HTML/動画スライド、画像への注釈、横からのスライド展開、講師／参加者ビューの分離、完全なバー非表示、グローバルショートカット、自動教材更新、自動アップデート、会議アプリとの連携、他OS対応。

## 6. 実装前・実装中に検証する事項

- AppBarとElectronの橋渡し方式、マルチモニター、DPIスケーリング、タスクバーとの競合、フルスクリーン例外、異常終了からの復旧。
- バー高（約90px）と折りたたみ高（約30–36px）の可読性、ボタンオーバーフローの操作性。
- スライドウィンドウのサイズ・ズーム上下限・最小／最大解像度（数値は未確定）。
- 初回教材選択、設定メニュー、画像表示中の再読み込みなどのUI詳細。
- Electron採用の最終判断、パッケージング・ウイルス対策製品との互換性。

## 7. 開発方針

MVP全体の要求は削らず、順に検証する。推奨段階：①枠なしUIと教材モデル ②画像ビューア ③AppBar連携・復旧 ④複数ディスプレイ ⑤ポータブル配布・実機受け入れ試験。各段階の完成はMVP全体の完成を意味しない。
