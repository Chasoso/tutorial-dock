# Baseline: ガイドバー基本表示

`docs/requirements.md` を正本として、R-01、R-04、R-05、R-09から対象部分を抽出した。以下のIDは要求書の正式IDに対応する。約90pxは暫定目標であり、確定値ではない。

| 要求ID | 確定要件 | 今回の確認 |
|---|---|---|
| R-01 | 選択ディスプレイ上端の枠なしガイドバー、通常表示時の固定高さ、番号/総数、タイトル/説明 | 上部表示、枠なし、ステップ切替で高さ不変、内容表示 |
| R-04 | 教材未読み込み時は空のガイドバーを表示し、ステップ移動を無効化 | 未読み込み状態と操作不変 |
| R-05 | 前/次で順序付きステップを切替、先頭/末尾で範囲外移動を防止 | 中間遷移と両端のno-op |
| R-09 | 主要操作はマウスのみで完結 | 前/次ボタンのマウス操作 |

## 暫定値・未確定事項

- 約90pxは暫定目標であり、生成物で確定値へ昇格させない。
- 教材は読み込み・検証済み固定fixtureとして扱う。これはYAML読み込みをMVPから除外する決定ではない。
- Electronの最終採用、実ソースパス、テスト基盤、IPC境界、アクセシビリティ詳細は未確定。

## 今回の対象外

R-01の折りたたみ、R-02のAppBar/作業領域予約、R-03のマルチディスプレイ、R-04のYAMLファイル選択、R-05のimage action実行、R-06画像ビューア、R-07再読み込み、R-08詳細エラー、R-09配布、グローバルショートカット。

## 生成物評価チェックリスト

1. R-01/R-04/R-05/R-09の対象要件が欠落していないか。
2. 約90pxを最終仕様にしていないか。
3. 対象外要件の完成を前提にしたタスクがないか。
4. 先頭・末尾・未読み込みが検証可能か。
5. 実装方式が仕様へ過剰に混入していないか。
6. fixtureがYAML機能の恒久除外と誤解されていないか。
